### 6.11 Audit (`bench/audit.py`, `app/views/audit.py`, `python -m subagent audit sample|report`)

- **Which episodes:** auto-mode ones. Human-reviewed episodes are left out unless `audit.include_human` (their output is the reviewer's corrected script, so auditing them measures the reviewer; their `edits.jsonl` already records every machine error exactly). The Audit screen lists them greyed as "not audited: reviewed by hand".
- **Sample** (per finished episode, reproducible: seeded by the episode id; `audit_sample.jsonl`, `AuditSample`): `audit.sample_size` random lines of the final script (approved, not deleted), split between flagged and unflagged lines in proportion and at least `audit.min_per_stratum` of each when available; "flagged" ignores `audit.ignore_flags` (reading speed says nothing about correctness). Plus up to `audit.max_disagreements` lines where the voice match (`fixed` / `new_voice`) or the talking sprite names someone else than the final speaker; these are reported separately (not random). An existing sample is kept (marks refer to it) unless `--redraw`.
- **Marking:** the Audit screen lists finished episodes (mode, lines, sampled, marked, error rate so far) with "Draw samples", "Audit selected episode" and "Report…". Auditing opens the review screen in audit mode: read-only, only the sampled lines, with the audit bar: ✓ / ✗ / n/a per aspect (speaker, OCR, translation, pronouns), a note, "All correct, next" (Ctrl+Enter), "Next unmarked"; the list's state column shows ✓ / ✗ / · per line. Marks (`AuditMark`; n/a kept apart from unmarked) autosave to `audit_marks.jsonl` (debounced, atomic). Marks change no output and teach no memory.
- **Report** (`_audit/report.md`, `_audit/summary.json` in the working folder): per aspect, the error rate over all lines of the audited episodes, estimated from the random sample stratified by episode and flagged / unflagged and weighted by line counts, with a 95% normal-approximation range (each stratum smoothed so a clean sample still has a range); flagged vs unflagged and disagreement-line error rates (Wilson 95%); per-episode table with mode and error rate. Only audited (by default auto-mode) episodes count.
- **Answers for a test set:** marking Speaker ✗ shows "Who really speaks" (characters and the episode's new voices); the mark keeps `correct_speaker` (`_new` = nobody known: an NPC or a character appearing for the first time, without an id: the right output is a blank speaker, so gold is None), and every mark keeps `speaker_value` (the line's speaker when marked). "Next unmarked" also stops at ✗ lines still missing that answer; the Audit screen shows "n answers missing".
- Series-neutral: nothing depends on the show.

### 6.11b Speaker benchmark (`bench/benchmark.py`, `python -m subagent audit benchmark`, Audit → Benchmark…)

- **Gold** (`audit.gold_speakers`): audited lines with a speaker verdict: ✓ → `speaker_value` (fallback: the line's current speaker), ✗ → `correct_speaker`; ✗ without an answer and n/a lines are left out (so before answers exist, "the audited output" scores 100% by construction).
- **Run:** for each episode with gold, a sandbox `<work>/_benchmark/<timestamp>-<label>/<episode>/` gets the episode's `events.jsonl` and `video.json` (OCR held fixed) and, for every other episode, `approved.jsonl` / `edits.jsonl` (the translator's reviewer-corrections block must match a real run); then the real stages audio → voice → cast → windows → translate run there with today's code and memory (memory is only read; nothing learned, nothing rendered). The translator's speaker is compared with the gold. Heavy sandbox files (audio, frames, embeddings) are deleted afterwards.
- **Output:** `report.md` / `summary.json` in the run folder: speaker accuracy now (stratified like the audit report) vs the audited output, accuracy on disagreement lines, per-episode counts, and every line whose speaker changed (✓/✗ against the gold); one line per run in `_benchmark/history.jsonl` (label, date, accuracies, cost). The Audit screen's "Benchmark history…" shows the table and the latest report.

### 6.11c OCR benchmark (`bench/ocr_benchmark.py`, `python -m subagent audit ocr`)

- **Episodes:** finished human-mode episodes. **Answer key:** their approved Chinese, corrected by `<work>/_ocr_benchmark/answer_key.json` (`corrections`: event id → on-screen text; `excluded`: event id → reason). Traditional and simplified variants count as equal (`VARIANTS`, extended 2026-10-06 with 淨溫題決懶臥 seen on screen); punctuation is ignored.
- **Run:** a sandbox `<work>/_ocr_benchmark/<timestamp>-<label>/` reruns ingest → OCR → events with today's code and config (bands are deleted afterwards; `events_raw.jsonl`, `ocr_raw.jsonl`, `ocr_samples/` are kept). `--existing` scores the OCR already on disk instead (instant).
- **Scores:** each approved line takes the event overlapping it most in time. Line accuracy (exact text), character error rate (a missed line counts all its characters), missed lines, junk events (events overlapping no approved line for half their time). `report.md` lists every wrong line; `summary.json`; one line per run in `_ocr_benchmark/history.jsonl`.

- **Re-mapping the key:** OCR re-runs renumber events (`ocr/events.py`). `python -m subagent audit remap-key --archive DIR` moves each correction and exclusion of the key archived in `DIR` (`answer_key.json` + each episode's old `events.jsonl`) to today's event overlapping its old event most in time (`ocr_benchmark.remap_key`), saves it as the current key and lists the ids that found no line. Old fragments merged into one new line: an exclusion moves only when the old excluded events together cover at least half of the new line (one about a fragment, "the sampled frame shows the previous line", says nothing about the whole line); corrections that disagree keep the one overlapping most. Both are listed in the key's `remapped` note.

### 6.11d Baseline (`bench/baseline.py`, `baseline.name`, `python -m subagent baseline freeze`)

- While `baseline.name` is set, `finish_review` copies the finished episode to `<work>/_baseline/<name>/<episode>/`: `approved.jsonl`, `edits.jsonl`, `events.jsonl`, `events_raw.jsonl`, `ocr_raw.jsonl`, `translations.jsonl`, `evaluations.jsonl`, `speakers.jsonl`, `new_voices.json`, `cast.jsonl`, `script_review.jsonl`, `pinyin.jsonl`, `video.json`, `state.json`, and for re-runs `voice_embeddings.npz`, `cast_embeddings.npy`, `memory_prefix.md`, `windows.json`; `manifest.json` records per episode the date, the files, the code and memory git commits, `memory_at_run` (the newest memory commit before the episode's `ocr_fix` stage started: the memory its machine output was made with; ep012 ran before ep011 was finished again, so this is not always the previous episode's commit) and a config hash. Finishing again replaces the copy; a failed copy is reported (`baseline_failed`) and never fails the episode. Character recognition gold: the lines with `cast_checked` (On screen checked on every line of 5 of the 16 episodes). `baseline freeze NAME [EPISODE...]` copies finished episodes by hand; `baseline complete NAME` adds the files and `memory_at_run` a baseline frozen by older code lacks (only from work folders whose `approved.jsonl` / `edits.jsonl` still equal the frozen ones; frozen files are never replaced) and copies the current OCR answer key to `<baseline>/answer_key.json`. `<work>/_baseline/` is its own git repository (user decision 2026-10-06; work data stays out of the project repo, NFR-S2): every file stored byte for byte (`.gitattributes` `* -text`, the snapshot check compares bytes), a README, and `<name>/references/` with the scores and machine files (`out/`, embeddings left out) of the recorded output and the reference runs. A change to the gold is a deliberate commit there. `aliases.json` in the baseline folder lists ids that name one character (a dropped NPC that came back and was given a new id in review; `npc_009_01` = `npc_004_01`, `npc_011_02` = `npc_008_02`, confirmed by the reviewer).

### 6.11e Benchmark suite (`bench/suite.py`, `bench/bench_run.py`, `python -m subagent bench score|run`)

- **Systems:** a folder of `<episode>/` machine files. `bench score` scores the baseline's own recorded output (what the reviewer worked from) or `--system DIR`; `bench run` makes a new one in a sandbox and scores it. Results: `<work>/_suite/<timestamp>-<label>/report.md` + `summary.json`, one line per run in `_suite/history.jsonl` (headline numbers).
- **1. OCR / Chinese:** raw OCR (`events_raw`), after OCR correction (`events`), and with the script review's fixes accepted, against the approved Chinese with the baseline's answer key; lines matched by time (`ocr_benchmark.score_episode`). The reviewer corrected the Chinese the pipeline gave them, so the later levels lean towards the recorded output.
- **2. Speaker / listener:** the translator's speaker and listener and the voice match's first candidate against the approved ones, split into known (in memory when the episode ran: `memory.db` at `memory_at_run`, read with `git show`), new and nobody; voice accuracy per status; lines where the translator overrode a sure voice. Aliases count as one character. Automatic ids are grouped (`suite.group_map`): each system id matching `<new_voice_prefix>_ddd_dd` maps one-to-one onto the gold id it shares most lines with, counted only on lines whose gold character was not in memory when the episode ran (automatic characters, candidates, characters created in review). Numbering never counts, and a main character's lines cannot be claimed by an NPC id.
- **3. Character recognition:** the On screen checked lines. Gold boxes as the reviewer left them (`suite.gold_boxes`, like `cast/learning.apply_review_edits`: labels, moved and drawn boxes, `_none`, the talking mark; a box the reviewer marked talking without a name is the speaker; an unrecognised box left alone stays unknown). Boxes matched at IoU >= 0.5: recall, precision, names right / unrecognised / wrong, talking sprite found, the talking sprite names the speaker, "nobody talks" agreed.
- **4. Translation + evaluator:** exact and mean similarity (`difflib`, punctuation and case ignored) to the approved Vietnamese over all lines and over the rewritten ones by cause (speaker or listener also edited, Chinese edited, pure); pronoun terms (`translate.pronoun_terms`) the same. Evaluator: the kept attempt's evaluation (`translate._rank`); catch rate on lines whose Vietnamese differs from the gold and false alarms on lines that match it, for "failed" and "doubt" (failed, a rule failure or any criterion <= 3), and the same for the speaker criterion against benchmark 2.
- **5. Script review:** the review draft (`review.original_draft`) against the reviewer's deletions: pre-deletion precision and recall by source (fragment rule, script removal reason), flagged lines deleted or with wrong Chinese, deletions neither pre-deleted nor flagged; suggested OCR fixes right / harmful (the line was right before).
- **Re-runs** (`bench run`): `<work>/_suite/<run>/` holds `memory/` (a git clone of the memory folder), `work/` and `out/<episode>/`. Nothing real is written (memory, work folders, registry, output folder). Per episode the stages before `--from` (default `ocr_fix`) are copied from the baseline (with the voice stage's `new_voices.json` / `voice_embeddings.npz`; `ocr` cannot be the first, the bands are not frozen: start from `ingest`). The stages from it to the script review run with today's code (audio added when the voice runs), the machine files go to `out/`, then the episode folder is replaced by the frozen review, so later episodes see the reviewer corrections as in the replay.
  - `snapshot`: each episode runs with its `memory_at_run`. The report lists episodes whose prompt memory prefix differs from the replay's (a check that the snapshot is right): with unchanged code the prefix is byte-identical and every LLM call comes from the cache.
  - `chain`: memory starts at ep001's (bootstrap) and learns from each frozen review in order (`Pipeline._memory_update`, voice and sprite learning, as finishing a human review), with today's code. The run's own output is scored, the gold is learned from (its translator proposals included). With some episodes chosen, the earlier ones are only learned from. The last episode is not learned from (nothing after it is scored). **Stopping and resuming:** a run can be stopped at any time (cancel the job); `--resume RUN` (the run folder, or its name under `_suite/`) continues it with the settings in its `run.json` (mode, start stage, episodes, label, cache): the episodes listed as done there are skipped, the one in progress is done again from the start, and a chain run first checks its memory out at the commit recorded after the last finished episode. Cost and the prefix check are computed from the run folder at the end, so a resumed run reports the same as one run in one go.
